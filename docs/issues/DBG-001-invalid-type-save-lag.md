# 非法文件类型保存前应立即校验，避免新增失败后无条件重载和整表刷新

关联 DBG-001 / DBG-011。原始复现版本 `c6dddf2`；当前本地工作区已修复并通过 Qt 控件自动回归，尚未提交代码或发布 GitHub Issue。正常 Windows 窗口的人工体验复测留给演示前检查。

## 复现步骤与原始结果

1. 加载独立副本的 530 条扩充记录，打开新增窗口。
2. 输入有效文件名、日期和非负数，文件类型填写 `213`。
3. 点击保存。

旧界面仅检查类型非空、不含点，因此仍调用 `addNew()`。业务层拒绝类型后，前端对所有失败统一调用 `recoverAfterError()`，先重载 CSV、索引，再重填整张表，最后显示错误。媒体 CSV 未写入，但编号已预留，编号状态文件可能改变；用户要等待数秒才能看到本应立即出现的输入提示。

## 根因与修复

两个独立因素叠加：类型白名单未在界面提交前校验；共享填表又逐格触发自动列宽扫描。

- 类型去空白、转大写后，调用已有 `MediaLibrary::supportedFileTypes()` 检查，非法类型直接提示支持范围、定位到类型字段并返回。
- 表单保留，不调用新增、重载或表格刷新；业务层白名单继续保留。
- `populateTable()` 的批量布局优化见 DBG-011；其他保存或外部文件异常仍保留原恢复流程。
