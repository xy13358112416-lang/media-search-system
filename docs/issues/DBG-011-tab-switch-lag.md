# 媒体库与检索页切换时重复计算列宽，530 条记录出现秒级卡顿

问题类型为界面性能缺陷。关联调试记录为 DBG-011，关联问题为 DBG-001 的原地刷新瓶颈。复现版本为 `c6dddf2`，已本地整合 `fix/qt-dropdown-style`。

当前状态：已在本地工作区修复并通过 Qt 控件自动回归，未提交或发布 GitHub Issue；正常 Windows 窗口的人工体验复测留给演示前检查。以下原始现象保留用于前后对照。

## 复现步骤

1. 使用扩充 CSV 的独立副本，加载 530 条记录。
2. 在媒体库中显示全部类型。
3. 切换到检索页，不填写条件。
4. 再切回媒体库，观察切页响应。

## 实际结果

用户观察到切换卡顿。Qt 控件探针触发实际页签切换回调后，媒体库切检索同步耗时约 5884 ms，检索切回媒体库约 5857 ms。每次均触发 6360 次列宽扫描和 3370800 次单元格尺寸计算。

相同探针对 30 条样例测得双向切页各约 21 ms，因此小样例下不容易察觉该问题。

以上为本机单轮 offscreen 控件诊断值，不是对所有 Windows 环境响应时间的保证。完整数据、计数方法和原始日志见 `docs/DEBUG_LOG.md` 的 DBG-011。

## 预期结果

切换页签时界面及时响应，列表、命中数和详情正确。数据未改变时避免重复全量布局，批量替换单元格时避免逐格重新扫描全部内容。

## 已定位原因

页签回调在进入检索时调用 `showSearchResults()`，进入媒体库时调用 `refresh()`，最终都调用 `populateTable()`。空条件下前后均为 530 行，行数不变，没有触发延迟布局；逐格替换内容会反复触发三列的自动列宽计算。

在临时探针中，切页前显式安排延迟布局后，媒体库切检索降至约 4 ms；临时使用固定列宽后，检索切媒体库约 1 ms。对照支持该原因判断，正式修复仍需回归验证。

## 已实施处理

共享 `populateTable()` 保存原列模式及绘制开关，填充期间将列模式临时切为 Fixed 并暂停重绘；完成后通过 qScopeGuard 恢复，让 Qt 统一处理自动列宽。零结果的提前返回同样恢复。保留全量填表，不增加缓存，因此等数量、不同内容的结果仍会更新。

新增 `frontend_regressions` 自动测试组和显式性能目标 `media_frontend_benchmark`。本轮五次测量、原始日志及复跑命令见 `docs/DEBUG_LOG.md` 的“DBG-001 / DBG-011 正式修复与复测”及 `docs/debug-probes/README.md`。

- [x] 记录同一机器、相同构建配置下五次修复前后耗时，包含布局处理，不包含人工操作等待。

- [x] 两次查询结果数相同但内容不同，也能正常刷新。
- [x] 新增、删除后重新切页，结果及时更新。
