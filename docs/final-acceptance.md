# 组合版本验收记录

## 本机验证的数据

- 账号、足迹和近 90 天行为使用 sample-data/simulation/generate.py 生成的 20 个模拟用户。用户 01 有 309 次浏览、95 次搜索，用户 20 无历史。
- 人物、作品、角色和别名使用人物导入集成测试临时库里的虚构记录。两条账号连接验证本人私有作品、公共仓库只读、关注隔离、删除最后一部作品后仍可取关。
- 资讯使用模拟响应里的 RSS、Atom 与错误响应。已验证首次缓存、失败保留旧缓存、Qt 显示过期缓存。示例域名是占位数据。
- 热榜 AI 摘要使用模拟模型 HTTP 服务。覆盖同会话重复请求、不同账号独立、超时回退、取消、断线和迟到响应。

## 现场待验

1. 在算法同学的服务器电脑上准备独立验收库，导入经组员核验的人物与作品关联，登记能够访问的真实 HTTPS feed。记录人物 ID、feed 地址、来源出处、核验日期和负责人。运行 media_person_source_config 的 --refresh-person 命令后，从关注中心核对标题、来源、日期和过期状态。
2. 两台电脑使用同一构建提交的程序，连接同一局域网 IP 和实际端口，以两个账号分别检查登录、搜索、公开仓库只读、人物关注、足迹和推荐。客户端和服务端发布目录需要保持完整。
3. 在服务器进程环境中设置 MEDIA_SERVER_DEEPSEEK_API_KEY。记录真实成功结果、超时情形和规则回退。自动回归只调用本机模拟模型。部署操作见 server/DEPLOYMENT.md。
4. 正式发布包从最终合入主线的提交重新构建，记录提交号、两端 EXE 的 SHA-256 和实机结果。

## 已知限制

- 资讯刷新由服务器运维工具触发，客户端读取服务器缓存。普通 RSS/Atom 条目只产生资讯，发布日历需要单独确认的发行数据。
- 新配置拒绝任何 URL 片段。已存在库中的旧错误记录需由管理员备份后核对处理。
- 本机模拟资讯、模拟模型和两条本机连接的结果均单独记录。真实外部站点、真实 DeepSeek 和双物理电脑仍待验收。
