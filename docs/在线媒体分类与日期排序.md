# 在线媒体分类与日期排序核对

核对日期：2026年11月24日。范围为当前在线主窗口的媒体库、检索结果和推荐列表；不修改媒体原始元数据、数据库、权限或检索算法。

## 核对前的实际情况

- 在线媒体库虽然显示文件类型，但按仓库与条目的返回顺序填表，没有统一分类、日期排序，媒体库页也没有单独的类型筛选框。
- 检索支持文件类型、发行年份/年月/日期条件，但结果按索引返回的ID顺序显示，没有按类型和日期组织。
- 默认场景的今日推荐在客户端使用每日种子抽取，可能改变服务端排序。动态推荐和仓库推荐原来已按返回顺序展示。
- 单机业务的MediaLibrary::records已有发行文本降序，不能据此认为在线页面已经满足要求；本次仅补齐在线页面。

## 修正后的展示规则

1. 先按文件类型分组。扩展名去除首尾空格、统一大写，按字母顺序排列，如FLAC、MP3、MP4；文件类型未记录的作品放在最后一组。文件类型与“电影/音乐”等内容类别是不同字段。
2. 每个类型组内，按已知的发行年、月、日逐级从近到远比较。完整日期用真实年月日；YYYY-MM只使用已知年、月；YYYY只使用已知年。缺失部分仅在比较键中记为低于所有有效月日的值，不生成或保存虚构日期。
3. 同一年的不同月份先比月份；同年同月下，完整日期排在只知年月的记录之前。只知年份的记录在该年已知月份的记录之后。因此2025-06排在2025-01-01前，不能笼统写成“所有完整日期优先于所有年月”。
4. 同类型内完全未知或格式无效的发行时间排在所有有效发行时间之后。不同类型仍优先保持类型分组，不把不同类型的未知日期混成一个日期组。
5. 类型及日期相同时，按作品名称排序；名称相同再按稳定的仓库/条目来源标识排序，避免服务器响应顺序改变后行顺序跳动。
6. 有效发行时间仍按YYYY、YYYY-MM、YYYY-MM-DD的原精度显示；未记录时间显示破折号。异常元数据仅在排序时归入未知，不补写日期。分类、排序和筛选不写回数据库。

同一文件类型下的示例：2026、2025-06-30、2025-06-01、2025-06、2025-01-01、2025、2024-12-31、未知。

## 首次加载、筛选与刷新

- 首次加载完当前用户可读的仓库后，对全体媒体统一排序，不是各仓库分别排序后拼接。
- 媒体库页增加“文件类型”下拉框，可选全部、未记录类型或已有扩展名；筛选后沿用同一排序规则。
- 检索仍使用MediaSearch取得匹配ID，再按统一媒体展示顺序显示匹配项。文件类型、导演、演员、关键词、发行时间和助手条件继续组合使用。
- 媒体刷新会重新读取并排序，保留仍存在的媒体类型筛选，并用上次已经提交的检索条件刷新结果；尚未提交的输入框编辑不会代替已提交条件。
- 初次加载、筛选、刷新和自动选中不产生行为事件；主动搜索仍记录一次搜索行为，主动点击仍携带原仓库/条目来源记录浏览。

## 推荐列表

在线今日推荐按返回顺序保留首次出现的作品，展示前6条，不再在客户端按日期种子抽取或按媒体类型/日期重排。动态推荐、仓库推荐继续按服务接口返回顺序展示。此规则不等于保证每天一定产生不同作品，具体结果由算法及候选决定。

## 修改位置

- frontend/online_window.cpp：日期比较键、类型分组与稳定排序；媒体库类型筛选；检索结果按统一顺序展示；刷新重新应用已提交条件而不新增行为；今日推荐保留返回顺序。
- frontend/tests/online_window_tests.cpp：乱序、跨仓库、混合日期精度、未知/异常日期、同日同名、类型大小写、类型筛选、刷新新增记录、未提交输入与行为次数的界面测试；今日/动态/仓库推荐顺序回归。

## 验收步骤

1. 登录在线界面，进入媒体库，确认同文件类型连续出现，每组内发行时间从近到远，未知在组内最后。
2. 选择一个文件类型，确认只显示该类型且日期顺序不变；选择“未记录文件类型”检查缺失字段的记录。
3. 在检索页提交可命中多条作品的条件，确认采用相同类型分组与日期排序；再组合文件类型和年份/年月/完整日期查询。
4. 刷新媒体，确认保持类型筛选、已提交检索及正确排序。可用新增/删除记录触发目录刷新检查变化，不要在正式库修改日期来凑测试数据。
5. 查看今日推荐、动态推荐和仓库推荐，确认没有被媒体库的类型/日期排序重排。

## 可用于报告的表述

系统支持按文件类型分类浏览，并在同类作品内根据已知发行年月日从近到远展示。对仅有年份、仅有年月和完整日期的资料保留原精度，不补造缺失日期；未知发行时间在同类中最后展示。首次加载、筛选、检索和刷新采用一致的展示顺序，推荐列表保持算法返回的顺序。
