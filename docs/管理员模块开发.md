# 在线管理员模块开发说明

本模块由陈智敏负责前端、网络接口、服务端业务与数据库接入。基线为用户于 2026 年 11 月 22 日提供的 media-search-system.7z，源码导入提交为 77913fe。开发日期为 2026 年 11 月 22 日。附带报告描述的原有仓库归属权限是本次兼容性检查的依据。

## 功能与入口

启动先显示身份选择窗口。选择“用户登录”或“管理员登录”后，进入对应标题的账号密码窗口，可通过“返回选择”重新选择。两种登录共用同一个 OnlineCareClient 和服务端数据库。服务器在登录响应的 user 中增加 is_admin 布尔值。客户端按照该值显示顶部“管理”按钮，点击后进入用户列表。旧服务器没有该字段时按普通用户解析。

管理窗口支持每页 100 个账号、上一页、下一页、刷新、创建普通用户、停用与启用普通用户、重置普通用户密码。创建账号的用户名与密码校验复用 WarehouseServer::addUser。用户名大小写规范化和密码加盐哈希沿用原实现。管理员可以在资源仓库页面向公开仓库新增和删除条目，页面保存成功后沿用原有刷新流程。

本次按账户管理和公开内容维护实现管理员模块。管理员的私有仓库访问范围仍按仓库归属判断。普通用户可继续维护自己的仓库，他人的公开仓库可浏览。管理窗口通过服务器回复展示失败，写入超时或断线使用现有 OutcomeUnknown 语义，操作人员应刷新确认后再决定是否重试。

## 首次创建管理员

2026年11月24日新增服务端本机 Qt 工具 media_admin_setup.exe。双击 01-Setup-Admin.cmd，读取 media-server.ini 的数据库路径，在窗口内填写用户名、密码和确认密码。密码框遮挡，成功后清空并锁定；已有任何管理员（含停用记录）时禁止重复初始化。普通客户端不包含这个工具，也没有新增管理员注册 RPC。

终端推荐入口为 --setup-admin，逐项输入用户名及两次密码。Windows 控制台在密码输入期间关闭回显，正常结束、错误及控制台中断时恢复。旧 --add-user/--add-admin 用户名 保留，交互终端增加确认密码，重定向单行密码维持自动脚本兼容。

initializeAdministrator 与账号插入在同一事务中检查已有管理员，失败回滚，避免并发重复初始化；首次初始化成功后保存 initialize_admin 审计。本机工具不监听网络，数据库文件写权限仍是管理边界，不额外假定操作者已通过 Windows 管理员鉴权。

新增文件为 server/admin_setup_main.cpp、admin_setup_dialog.h/.cpp、console_input.h/.cpp，分别负责本机工具入口、Qt 表单和隐藏的终端输入。原有 addUser 和网络登录签名保持兼容。测试覆盖错误输入、重复初始化、已有普通账号不提权、审计回滚、并发和原管理员操作。

## 控制台维护入口

在服务器停止运行时，对实际业务数据库执行以下命令。命令随后从标准输入收取密码，至少 6 个字符，密码通过 libsodium 的加盐密码哈希持久化。

```powershell
.\media_server.exe --db "E:\实际目录\media-demo-200.sqlite" --add-admin admin
```

命令成功后退出。按原启动配置启动服务器，再在客户端选择“管理员登录”并使用该账号登录。请填写不同于现有用户名的新账号名。原来的 --add-user 继续创建普通用户。管理窗口创建的账号固定是普通用户。首个管理员也可由上述本机 Qt 工具创建；额外管理员由服务器控制台维护。当前管理窗口提供普通用户管理，管理员密码维护需要后续专用控制台入口。

## 数据库升级

openDatabase 在原有初始化事务里创建两张附加表。network_users 及原有业务表沿用原结构，旧账号通过 LEFT JOIN 默认得到普通用户角色和启用状态。

- network_user_access 以 user_id 为主键并引用 network_users，包含受 0/1 CHECK 约束的 is_admin 和 disabled。
- admin_audit 保存自增 id、actor_id、target_id、action、occurred_at_utc。操作类型区分账号与条目，target_id 分别指向用户或条目编号。时间为 UTC Unix 秒。

升级前应在停服状态备份原数据库，生产使用配置仍指向原文件。新建管理员账号及权限记录在同一事务保存。创建用户、停用、启用、密码重置、管理员新增和删除媒体的审计记录与业务写入原子提交。密码和哈希均不进入审计字段。

停用、启用或密码重置成功后，服务器撤销目标用户所有连接上的会话。断连路径取消关联的推荐任务并清理 token。界面沿用断连回登录机制，管理弹窗随之关闭。

## 登录入口校验

新登录窗口调用 WarehouseService::loginAs，传递 LoginRole::User 或 LoginRole::Administrator。网络 login 请求增加可选 login_role 字段，取值为 user 或 admin。服务端完成密码和停用状态校验后，将所选角色与数据库角色比较，匹配后才创建会话及 token。

普通账号从管理员入口、管理员账号从用户入口登录，均返回 PermissionDenied，客户端保留当前登录窗口供重试或返回选择。所选角色不参与数据库角色赋值。旧 login 调用可省略 login_role，仍由服务器按账号实际角色返回身份。新客户端还会核对响应身份，角色不符时断开连接。

返回选择时清空密码、断开连接并使在途登录回调失效。再次选择后重新连接。用户名按管理员和普通用户分别记忆，密码不持久化。退出账号或断线后，再次进入身份选择流程。

## 网络接口

沿用 4 字节大端长度加 UTF-8 JSON，req_id 与 token 的验证、请求匹配、超时和断连处理共用 WarehouseClient。账户身份由连接会话决定。

- admin_list_users 接受字符串 offset，返回 users 数组及 has_more，每页最多 100 个。用户项包含 user_id、username、is_admin、disabled。
- admin_create_user 接受 username、password。角色由服务器固定为普通用户。
- admin_set_disabled 接受 user_id 字符串和 disabled 布尔值。
- admin_reset_password 接受 user_id 字符串和 password。
- add_item、remove_item 复用原有仓库条目接口，服务器额外允许管理员维护公开仓库。

每个管理接口都先用当前连接会话到数据库检查管理员身份。客户端传入的 is_admin 或用户身份字段不能授予权限。接口拒绝管理管理员账号与修改自身状态，确保管理员入口持续可用。客户端所有管理写入沿用请求只完成一次的逻辑，迟到响应由原有 pending 表丢弃。

## 构建

使用项目原来的 Qt 6、C++17、CMake、Ninja 和 libsodium 环境。当前机器验证目录为 build/admin-module，源码目录为 media-search-frontend。

```powershell
cmake -S . -B build -G Ninja -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

新包应同时更新客户端与服务器，数据库可继续使用原路径。旧客户端仍能使用基础仓库接口，新客户端连接旧服务器时按普通用户展示。本次以用户提供的最新源码为准，包含人物主页查询、联网资料解析与对应测试，随后整合双登录入口与管理员功能。源码导入与管理员整合分别保留提交，便于核对。
