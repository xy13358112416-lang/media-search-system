# 管理员初始化与升级测试

适用版本0.2.0-admin.2，日期2026年11月24日。代码提交与两端版本见各包的VERSION.txt。客户端登录布局沿用原版，新增创建窗口只放在服务端包内。

## 开始前

新环境完整解压服务端，默认演示库包含500条作品和200个模拟账号，没有预设管理员。已有环境先停服并备份原数据库，继续让media-server.ini指向原文件，升级只替换程序和依赖。初始化工具使用配置文件所指向的同一数据库；不要把新包演示库覆盖到原库。

初始化只要求能操作服务端本机文件，不需要API Key，也不监听网络。数据库和初始化工具应只允许服务器维护者写入。本机窗口与终端均不是额外的Windows管理员身份认证。

## B01 Qt创建首个管理员

1. 在服务端电脑双击01-Setup-Admin.cmd，确认标题为“服务端管理员初始化”。
2. 核对数据库完整路径；输入一个不存在的用户名以及两次相同的密码，点击创建。
3. 关闭窗口，配置需要的DeepSeek Key后启动start-server.cmd。
4. 客户端选择管理员登录，用刚创建的账号登录，检查顶部管理按钮及用户列表。

预期创建成功后密码清空、表单锁定；数据库保存哈希与管理员角色，并产生initialize_admin审计。初始化期间不发模型请求。记录 □通过 □失败；证据________。

## B02 空输入、短密码和确认不一致

1. 用独立无管理员测试库打开窗口，分别测试空用户名、空密码、两次不同密码。

## B03 已有管理员与旧数据保护

1. 停止服务器，备份并记录已有库的账号、仓库和历史。
2. 用Qt初始化工具打开已有管理员的库，检查创建按钮及提示。
3. 用--setup-admin再对同一个库尝试初始化。
4. 启动新服务器，用原管理员和原普通账号登录，检查仓库、历史和原密码。

预期窗口锁定，命令拒绝重复初始化，原账号、密码、权限及业务数据保留。即使管理员在数据库中为停用状态，也不允许通过初始化覆盖。记录 □通过 □失败；证据________。

## B05 多窗口与并发

1. 在同一个无管理员测试库打开两个初始化窗口。
2. 先在第一个窗口创建，再在第二个窗口填写另一个名字并创建。
3. 两个进程并发执行--setup-admin的场景由admin_setup_cli自动测试验证。

预期仅一个首次初始化成功，第二个窗口提示已有管理员并锁定，不创建第二个账号。检查与写入在同一数据库事务中。记录 □通过 □失败；证据________。

## B06 终端逐项输入与隐藏密码

1. 对独立新库双击01-Setup-Admin-Terminal.cmd，或执行media_server.exe --db 测试库路径 --setup-admin。
2. 依次输入用户名、密码、确认密码，各项输入后回车。
3. 确认两次密码均不显示在终端；成功后普通终端输入恢复回显。
4. 在另一新库测试确认不同及输入中断，不应产生账号。

预期不需要在命令里写用户名或密码，失败不创建账号。Windows真实控制台模式由admin_setup_console自动测试。记录 □通过 □失败；证据________。

## B07 路径、配置与数据库失败

1. 从其他工作目录用--config指定服务端配置文件打开工具，检查数据库路径相对配置文件解析。
2. 通过“选择数据库”切换到独立测试库，表单应重新检查管理员状态、清空密码。
3. 指定父目录不存在或无法写入的测试路径，确认错误提示和创建按钮关闭。

预期不会因当前目录不同而误开另一份库；错误不伪装成初始化成功。新建数据库仅用于明确选定的新环境，已有库须备份。记录 □通过 □失败；证据________。
