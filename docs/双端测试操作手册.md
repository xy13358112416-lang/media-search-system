# 多媒体系统双端测试操作手册

适用发布版本为 0.2.0-admin.4，日期为 2026 年 11 月 24 日。本版修复人物联网来源的百度百科导航参数误判，并保留密码字符数、错误提示及独立启用/停用账号操作。源码提交号见包内 VERSION.txt。

本手册按首次部署、管理员验收、原功能回归、DeepSeek 联调和异常恢复的顺序执行。初始化专项步骤见同目录《管理员初始化与升级测试》；两台实体电脑及用户自己的真实 API 需要依照下文实测。每个用例末尾的记录由测试人员填写。

## 一 文件与电脑分配

- MediaSearch-client-0.2.0-admin.4.zip 放到每台需要操作界面的电脑，解压后进入 client 目录，运行 Start-Client.cmd。
- MediaSearch-server-0.2.0-admin.4.zip 放到负责服务器的电脑，解压后进入 server 目录。该电脑需要能够访问互联网以调用 DeepSeek。
- MediaSearch-source-0.2.0-admin.4.zip 用于代码阅读与开发，源码在 media-search-system 目录中。运行双端测试时使用上面两个运行包。
- 本测试手册随双端包放在各自的 docs 目录，也提供独立下载。

电脑 A 运行服务端，并可同时运行一个客户端；电脑 B 运行另一个客户端。两台电脑连接同一个可互通的 Wi-Fi 或有线局域网。建议在不同文件夹完整解压两个包，保持 EXE、DLL、配置文件和插件的相对位置。

## 二 首次启动服务端

### 1 选择测试数据库

新服务端包的默认演示库位于 server/data/demo/media-demo-200.sqlite，内置 500 条作品和 200 个模拟账号，模拟账号密码为 demo-only-123。已按最新源码导入 Queen、The Beatles、周杰伦的来源人物及 150 条音乐作品关联，并清除了 150 条电视剧的模拟导演占位值；未知导演显示为空或破折号。此次验收推荐额外建立 test_alice 和 test_bob，以便辨认本次实际操作。

如果要保留现有账号、仓库和浏览记录，先关闭旧服务端，再备份原 SQLite 文件，把 server/media-server.ini 的 database 改为该文件的绝对路径。下面所有创建账号命令中的 --db 路径也应改成同一个文件。已有业务库和包内演示库应分别存放。

### 2 在服务端目录打开 PowerShell

在 Windows 文件资源管理器进入解压后的 server 目录，在地址栏输入 powershell 并按回车。后续命令均在这个窗口执行。若之前仍运行着服务端，先在其窗口按 Ctrl+C 停止。

### 3 创建第一个管理员

推荐使用服务端本机的 Qt 窗口。先停止服务器，然后双击 server 目录中的 **01-Setup-Admin.cmd**，窗口标题为“服务端管理员初始化”。

1. 检查窗口中的数据库路径，必须与 media-server.ini 的 database 指向同一文件。需要时点击“选择数据库”。
2. 分别填写管理员账号、密码和确认密码。用户名最多64个字符；密码至少6个字符，UTF-8编码后最多1024字节。两个密码框均隐藏显示。
3. 点击“创建管理员”。成功后密码清空，创建按钮关闭。关闭初始化窗口，再执行后面的启动服务步骤。
4. 再次打开时应提示“已有管理员”，不能覆盖、重置或再次初始化。原库已有管理员时直接使用原账号，不需要重新创建。

初始化工具仅操作选定的本机数据库，不监听网络，不需要 DeepSeek Key。客户端登录页仍只有用户与管理员登录入口，不开放管理员注册。本机工具和数据库的访问权限应交给服务器维护者管理；本机窗口不等于 Windows 系统管理员鉴权。

也可双击 **01-Setup-Admin-Terminal.cmd**，或在服务端目录的 PowerShell 执行：

```powershell
.\media_server.exe --config .\media-server.ini --setup-admin
```

按提示依次填写用户名、密码和确认密码，每项输入后回车。密码不回显，用户名大小写视为同一名字，密码区分大小写。两次密码不一致、输入中断或数据库已有管理员时，初始化失败且不创建账号。

旧的 --add-admin 用户名 命令保留给拥有数据库写权限的部署维护者，用于明确增加其他管理员。直接在交互终端使用时输入两次隐藏密码；自动脚本通过标准输入重定向一行密码的方式继续兼容。该维护入口与只能创建首个管理员的初始化窗口有不同用途。

### 4 输入自己的 DeepSeek Key

在同一个 PowerShell 执行以下命令，按提示输入自己的 Key。输入内容隐藏，Key 保存在当前进程环境中。

```powershell
$secureKey = Read-Host '请输入 DeepSeek API Key' -AsSecureString
$env:MEDIA_SERVER_DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', $secureKey).Password
Remove-Variable secureKey
```

统一使用 MEDIA_SERVER_DEEPSEEK_API_KEY。账号登录密码由第 3 步设置，模型 Key 由本步骤配置。Key 留在服务器上，分享测试截图时应避开 Key 与密码输入内容。关闭这个 PowerShell 后，下一次需要重新设置该变量。

### 5 启动服务

继续在同一个 PowerShell 运行。

```powershell
.\media_server.exe --config .\media-server.ini
```

启动后保持该窗口打开。包内配置监听 0.0.0.0，端口为 8765。0.0.0.0 用于服务端监听，客户端填写下一步查到的具体 IPv4。

### 6 查服务器 IP 并测试端口

在电脑 A 另开一个 PowerShell，运行 ipconfig，找到当前 Wi-Fi 或以太网的 IPv4 地址。例如实际地址是 192.168.43.8，就把它发给电脑 B。

电脑 B 执行下面命令，将示例 IP 替换成电脑 A 的实际地址。

```powershell
Test-NetConnection -ComputerName 192.168.43.8 -Port 8765
```

预期 TcpTestSucceeded 为 True。若为 False，依次检查服务端窗口是否仍打开、IP 是否属于当前网络、端口是否 8765、两台电脑是否处于允许互访的局域网，以及 Windows 防火墙是否允许此服务端通过当前网络。酒店、校园访客网络可能隔离客户端。

### 7 启动两个客户端

电脑 A、B 分别进入解压后的 client 目录，双击 Start-Client.cmd。电脑 A 可填 127.0.0.1，电脑 B 填电脑 A 的局域网 IPv4。选择登录身份后，点击“更改服务器”，设置地址和 8765，再点“重新连接”。成功后输入账号密码并点“登录”。地址记忆可能来自本机之前的登录，本次应实际核对。

### T15 失败回退与恢复

1. 在服务器窗口按 Ctrl+C 停服，并保留原 Key 于临时变量。
2. 使用以下命令设置一个明确无效的测试 Key，再启动服务。

```powershell
$savedKey = $env:MEDIA_SERVER_DEEPSEEK_API_KEY
$env:MEDIA_SERVER_DEEPSEEK_API_KEY = 'invalid-key-for-acceptance'
.\media_server.exe --config .\media-server.ini
```

3. 客户端重新登录，执行一次推荐与一次联网人物查询。
4. 记录推荐是否明确回退，人物查询是否显示失败提示。
5. 按 Ctrl+C 停服，恢复 Key，再启动并重试。

```powershell
$env:MEDIA_SERVER_DEEPSEEK_API_KEY = $savedKey
Remove-Variable savedKey
```
