# 扩充数据说明

`media_records_expanded.csv` 包含 530 条记录：原项目 30 条虚构样例，以及从 UCI Movie 数据的本地下载片段中按影片编号和标题匹配出的 500 条影片记录。这个文件独立于现有媒体库，不能直接覆盖已有 CSV。

## 数据来源与限制

- UCI Movie 数据集：<https://archive.ics.uci.edu/dataset/132/movie>，数据集页面标示 CC BY 4.0。数据内容为 1990 年代收集的旧影片资料，有缺失和原始数据错误的可能，未逐条人工核实。
- 参考 GitHub 中的 UCI 数据转换项目：<https://github.com/cernoch/movies>。本批数据从 UCI 的 `main.html` 和 `casts.html` 直接提取，不是从该 GitHub 仓库下载。
- 本机下载两份源文件时连接中断，均是**不完整的片段**；`source_snapshot.json` 记录片段长度和哈希。这 500 条是片段内按源编号排序得到的可匹配子集，不代表整个数据集，也不保证具有代表性。
- 影片标题、导演写法、年份、演员来自来源中匹配的条目。导演可能是来源的简称；演员取来源中前五个可识别人名，不保证均是主要演员。类别仅对来源中能识别的少量类别代码做映射，识别不了的留空。
- 来源只提供年份，`YYYY-01-01` 是为了兼容系统日期字段的占位值，不代表真实发行日期。新增 500 条的 `.mp4` 文件名和类型是虚拟占位；媒体文件并不存在，大小 `0` 表示未知，浏览次数 `0` 为演示初始值，空奖项列表表示未知。这些值不应当作真实文件大小、热度、获奖或发行日。
- `provenance.csv` 逐条记录来源类型、UCI 源编号和日期精度。原来的 30 条仍是虚构数据，可以通过该文件区分。若要复现，运行 `build_data.py`；它依赖 `lxml` 和随文件提供的来源片段，本次使用 lxml 6.1.1、libxml2 2.11.9。重新运行会覆盖此目录下的扩充 CSV 和来源表。

## 已验证

使用项目 `CsvMediaRepository` 读取扩充 CSV 成功，共 530 条、ID 唯一；原虚构样例查询“林川 + 陈明 + MP4”仍命中 `M000001`、`M000002`。新增部分有 146 个来源导演写法、1646 个演员写法；其中 186 条类别未识别。统计仅描述这次导出的子集。

## 使用方式

先保留原库备份，在独立目录复制此 CSV，用程序选择副本进行演示。新数据的 `M000031` 及后续编号只保证在本文件中唯一；与其他现有媒体库合并前，必须检查并处理 ID 冲突。若迁移已有媒体库，需要同时保留对应的 `.id-sequence` 编号状态文件；不要用此扩充 CSV 替换正式库或其状态文件。
