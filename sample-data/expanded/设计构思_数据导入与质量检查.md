# 数据导入与质量检查：课程项目设计构思

## 应用场景

团队的多媒体库原先只有少量手工录入数据；从公开电影资料扩充后，可能出现导演或演员写法不统一、同名作品、日期只有年份、类型和浏览次数缺失等情况。系统如果把这些数据直接当成完整真实记录，组合检索和基于浏览次数的推荐就容易产生误解。

本方案面向主逻辑负责的数据部分，提出一个“导入预检 → 疑似重复提示 → 人工确认 → 保存并更新索引”的流程。它是待讨论的设计，不是本次已经实现的功能，也不声称算法具有新颖的学术贡献。

## 设计一：带原因的数据预检

导入时逐行检查字段数量、唯一 ID、日期往返、文件类型白名单及演员 JSON 数组；对每一行给出行号和问题，而不是只返回“CSV 无效”。另统计来源未知、只有年份、文件大小未知等情况。使用者选择修正或跳过问题记录，再生成导入预览；预览阶段不修改现有库。

本次 500 条 UCI 条目正好能展示这个场景：日期只有年份，大小和浏览次数都是占位值，186 条类别未识别。需要一份伴随的来源/精度表才能区分“真实的 0”和“未知”，仅凭现有十列不能可靠判断。当前系统尚未实现这个预检界面或伴随表读取。

## 设计二：疑似重复检测算法

不要按标题直接删除：同名电影可能是不同年份的作品，也可能是同一电影的不同文件版本。预检先生成候选对，再由人确认。

1. **候选生成**：标题去掉扩展名，进行 Unicode 规范化、大小写与空白处理；按规范化标题的字符二元组建立倒排表，找共享二元组的候选。短标题设单独规则。这个步骤可能漏掉改名较大的重复项，需要实测而非假设完美。
2. **候选评分**：仅对双方都有的字段比较，建议初始权重为标题 0.60、导演 0.25、年份 0.15；标题采用字符二元组 Jaccard，导演按规范化文本精确匹配，年份一致记 1。缺失字段不计入分母，至少要求标题可比较。四位年份只作年份比较，不把占位的 1 月 1 日当真实发行日。
3. **提示而非自动合并**：分数达到待验证阈值的候选展示双方字段和各项得分，由用户选择保留、跳过或作为不同版本导入；所有操作保留各自 ID。

例子：`The Example.mp4` 和 `the example.mkv` 标题规范化后相同，导演、年份也相同，系统提示可能重复；若是同名但不同年份的翻拍影片，则同时展示年份差异，由人决定。阈值与权重只是初始方案，需通过标注数据调整。

GitHub 上 OpenRefine 的字符匹配与聚类实践说明了此类方法可辅助发现不同写法，也明确指出字符相似不等于语义相同：<https://github.com/OpenRefine/openrefine.org/blob/master/docs/technical-reference/clustering-in-depth.md>。

## 设计三：可解释的数据报告与答辩展示

一次导入后给出总行数、可导入数、错误原因分布、疑似重复对数，以及来源和日期精度统计。用一条具体记录展示“来源只有年份 → 日字段是占位 → 不计作精确发行日”，让观众能追溯字段的意义。

验收可以构造一个单独的测试 CSV，其中人工标记若干确实重复、同名但不同影片、缺失导演和异常格式；检查报告原因、人工确认结果，以及确认后重启加载和原有检索结果。比较全量两两比对与候选生成的**候选数量、耗时和已标注重复对召回率**；先确认结果，再比较性能。530 条全量无序两两组合为 140185 对。数据集、测试样本量、阈值和机器条件必须一起报告；目前还没有该算法的实测结果。

## 职责边界和下一步

先在主逻辑中实现可独立测试的预检报告和候选对接口；由 Qt 同学决定如何展示列表及确认按钮。原有检索索引、推荐逻辑由相应同学维护；实际写入成功后沿用现有索引更新流程。第一步应先与组员约定来源表、候选结果结构和未知值的显示规则，再决定是否将设计纳入项目。
