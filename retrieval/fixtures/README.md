# 媒体 CSV 联调样例

`media_records.example.csv` 含 8 条虚构记录。它用于先确认导入格式，再给爬取脚本和 CSV 读写模块使用同一套规则。列名和顺序沿用 `DATA_INTERFACES.md`。

## 待确认的列表编码

- 样例采用 UTF-8，`actors` 和 `awards` 各占一列，字段内容为 JSON 字符串数组。多人使用 `["演员甲","演员乙"]`，空列表使用 `[]`。
- CSV 外层照常转义。字段含逗号或双引号时，整格加双引号，字段中的双引号成对写。例如上面的多人数组在 CSV 文件中是 `"[""演员甲"",""演员乙""]"`。这份样例每条记录占一行。
- 读取时先用 CSV 规则拆列并还原外层引号，再用 Qt 的 `QJsonDocument::fromJson` 解出两个字符串数组，填入 `QStringList`。每个数组元素对应一名演员或一个奖项。
- `file_type` 为不带点的大写扩展名，`file_size` 为字节数，`view_count` 为非负整数，日期用 `YYYY-MM-DD`。类别是独立的最后一列，可以留空。原来的九列表头按共享约定读入时，类别留空。

## 联调时可手算的结果

| 操作 | 预期结果 |
|---|---|
| 查询导演甲 | `M000001`、`M000002`、`M000004` |
| 查询演员乙 | `M000001`、`M000003` |
| 查询导演甲、演员乙且文件类型为 MP4 | 仅 `M000001` |
| 查询演员丙 | 仅 `M000004`，文件名完整显示为 `海边,片段.mp4` |
| 删除 `M000001` 后重查上述组合条件 | 结果为空。同名的 `M000006` 仍是一条独立记录 |
| 检查导入后的空列表和引号 | `M000005` 的演员列表为空。`M000008` 的奖项为 `观众"选择"奖` |

等主逻辑同学确认编码后，再把这套规则写进正式的共享接口文档。CSV 加载器接好后可用这份文件验收读取、查询和保存回读。
